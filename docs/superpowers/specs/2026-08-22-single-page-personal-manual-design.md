# 单页个人说明书改版设计

**日期：** 2026-08-22
**状态：** 已批准，待实施计划

## 1. 目标与范围

将现有多页面个人网站收束为一页式“个人说明书”，主要服务招聘方与潜在合作方。访客应能在一个连续页面中快速判断站主的职业定位、核心能力、经历与项目，并通过文章或外部链接进一步了解细节。

本次改版包含：

- 首页成为唯一主要内容入口，不再提供“首页 / 项目 / 博客 / 关于”多 Tab 导航。
- 页面主体按简历式履历主线从上到下组织。
- 桌面端增加随页面滚动保持可见的个人信息卡；移动端改为普通文档流卡片。
- 项目与文章在各自板块内以“简介 + 链接”卡片展示。
- 保留 Markdown 文章详情页，首页文章卡直接链接到详情页。
- 为旧 `/projects/`、`/blog/`、`/about/` 地址保留跳转兼容，避免历史链接立即失效。
- 继续使用 Jekyll、Liquid、SCSS 和少量原生 JavaScript，不引入前端框架或后端。

本次不虚构真实履历。现有已公开的姓名、职业定位与技能可以继续使用；公司、任职时间、教育、具体成果及无法确认的信息使用明确的待替换占位。

## 2. 页面架构与阅读动线

桌面端采用“左侧主内容 + 右侧粘性个人信息卡”的双栏布局。右栏宽度固定在适合快速扫描的范围内，左栏承担连续阅读。移动端改为单列，个人信息卡置于开场介绍之后并取消粘性定位。

正文从上到下包含以下板块：

### 2.1 开场 / 自我定位

用一句职业定位和一段简短自述回答：站主是谁、当前在做什么、能为团队或合作方带来什么价值。开场区域提供少量页内锚点，直达核心能力、经历与项目、技术文章及联系方式。

### 2.2 核心能力

将现有技能整理成招聘与合作方易判断的能力组，而非单纯标签堆叠。首版能力组包括：

- AI 驱动的编码算法迭代；
- 视频编解码算法优化（H.265 / H.266 / AV1 / NVC）；
- VOD / Live / RTC 场景 QoS / QoE 优化。

每组能力包含简短说明，描述其解决的问题或应用场景。未提供、无法验证的量化成果不得写入。

### 2.3 工作与项目经历

经历以简历式条目展示，包括时间范围、角色或工作场景、简介以及职责 / 成果要点。首版使用清晰标注的待替换占位，不声明未经确认的公司、年限、教育或成果。

经历板块后展示全部代表项目。项目卡包含名称、简介、技术标签，以及实际存在时才显示的项目地址或代码仓库链接。项目不再设置站内详情页。

### 2.4 技术文章

首页展示全部文章卡片，不再通过“查看全部”进入独立博客列表。每张卡包含标题、日期、摘要、标签和“阅读全文”链接；链接指向保留的文章详情页 `/blog/<slug>/`。

### 2.5 联系与页脚

联系方式板块仅渲染实际提供且可公开的邮箱、GitHub、LinkedIn 或简历链接。空字段不输出链接。页脚保留简洁版权信息及必要的技术说明。

## 3. 个人信息卡

个人信息卡是供访客快速判断的固定摘要区，包含：

- 姓名；
- 一句职业定位；
- 当前关注方向；
- 核心技能标签；
- 实际存在的公开联系方式与外部链接。

桌面宽屏下使用 `position: sticky`，在适当的顶部偏移位置随页面滚动，并受主布局容器边界限制。卡片不得遮挡页脚、溢出视口或造成独立滚动区域。窄屏下取消粘性定位，作为普通信息卡进入文档流。

## 4. 内容模型与维护方式

### 4.1 全局配置

`_config.yml` 继续维护：

- 站点名称与描述；
- 姓名、角色和个人简介；
- 邮箱及外部链接；
- 核心技能；
- 当前关注方向。

现有结构可在保持兼容的前提下补充关注方向字段。所有未知资料继续使用统一、显式的“TODO: 替换为……”占位。

### 4.2 经历数据

新增 `_data/experience.yml`。每条经历包含：

- `period`：时间范围；
- `role`：角色或场景；
- `summary`：一句简介；
- `highlights`：职责或成果要点列表。

页面按数据顺序渲染经历条目。首版数据仅用于展示可编辑结构，不虚构事实。

### 4.3 项目数据

继续使用 `_data/projects.yml`。首页展示全部项目，不再区分首页精选与独立项目列表；为兼容现有数据可暂时保留 `featured` 字段，但页面不依赖它过滤项目。

项目链接按以下规则渲染：

- `project_url` 非空时显示“查看项目”；
- `repository_url` 非空时显示“查看代码”；
- 两者均为空时不显示链接区，不生成空链接。

### 4.4 文章数据

继续使用 `_posts/` 与标准 Jekyll Front Matter。首页遍历 `site.posts` 展示全部文章。文章卡优先使用 `description`，缺失时回退为正文摘要。文章详情布局、Markdown 渲染和 `/blog/:title/` 永久链接规则保持不变。

## 5. 路由与兼容策略

- `/`：唯一主要内容页面，承载完整个人说明书。
- `/blog/<slug>/`：保留文章详情页面。
- `/projects/`：兼容页面，跳转到 `/#projects`。
- `/blog/`：兼容页面，跳转到 `/#articles`。
- `/about/`：兼容页面，跳转到 `/#experience` 或首页最接近原“关于”内容的锚点。
- RSS、站点地图、robots.txt 和 404 页面继续保留。

兼容跳转页采用静态页面可用的最小方案：提供规范链接、即时跳转以及可点击的回退链接。不得依赖服务器端重定向。

## 6. 组件边界

### `index.html`

负责定义首页整体双栏布局及章节顺序，读取全局配置、经历数据、项目数据和文章集合。它只编排区块，不重复实现卡片内部细节。

### `_includes/profile-card.html`（新增）

只负责个人信息卡的语义结构、技能标签和有效联系方式渲染。可同时用于桌面与移动布局，不复制两份内容。

### `_includes/experience-item.html`（新增）

只负责一条经历的时间、角色、简介和要点列表；不得在组件中硬编码具体履历。

### `_includes/project-card.html`

调整为单页项目卡，负责项目名称、简介、技术标签和有效外链。

### `_includes/post-card.html`

调整为单页文章卡，负责标题、日期、摘要、标签和文章详情链接。

### `_includes/header.html`

收束为极简品牌区和主题切换。站点品牌链接回首页，不再遍历多 Tab 导航，也不保留移动菜单按钮。

### `assets/css/main.scss`

负责双栏布局、粘性侧栏、章节层级、经历条目、项目 / 文章卡、浅深色主题、响应式断点和减少动态效果支持。

### `assets/js/site.js`

删除移动菜单逻辑，保留主题切换及本地偏好保存。页内跳转优先使用原生锚点与 CSS，仅在必要时增加少量脚本。

## 7. 视觉与交互设计

整体延续现有浅色默认的科技极简方向，但从产品式首页转为可扫描、可连续阅读的技术简历：

- 使用较宽正文列、明显章节标题和克制的区块编号；
- 减少无信息价值的大面积装饰和营销式按钮；
- 侧栏卡片使用细边框、柔和底色和有限阴影，不使用霓虹或复杂动画；
- 经历采用紧凑的时间轴或时间标记，突出角色、场景和贡献；
- 项目卡与文章卡共享一致的边框、间距和链接层级；
- 使用现有低饱和蓝紫作为链接、标签与键盘焦点的统一强调色；
- 保留浅色 / 深色切换，手动选择继续保存至 `localStorage`；
- 锚点目标设置合理的 `scroll-margin-top`；
- `prefers-reduced-motion: reduce` 时关闭平滑滚动和非必要过渡。

## 8. 空状态、异常与可访问性

- 没有经历数据时，显示简短的待补充提示，不产生破碎列表。
- 没有项目时，显示“项目内容待补充”空状态。
- 没有文章时，显示“文章内容待更新”空状态。
- 邮箱、社交链接、简历地址或项目链接为空时，对应控件不渲染。
- 所有外部链接使用明确文字；若新窗口打开，则补充安全属性和可理解的访问提示。
- 使用语义化 `<main>`、`<aside>`、`<section>`、标题层级和列表结构。
- 主题按钮保留可见焦点、正确的 `aria-pressed` 与动态标签。
- 布局在放大文字、键盘操作及窄屏下不得产生横向滚动或内容遮挡。
- 粘性侧栏只是视觉增强；不支持 sticky 时，内容仍按正常文档流完整可读。

## 9. 技术边界

本次不添加：

- 前端框架或新的构建系统；
- 数据库、应用服务器、登录、评论或联系表单；
- 访问统计或第三方追踪；
- 第三方字体依赖；
- 项目站内详情页；
- 无法佐证的企业、经历、教育或量化成果。

实施完成后删除所有不再承担功能且未被模板引用的旧页面、组件、脚本和样式。旧 `/projects/`、`/blog/`、`/about/` 文件仅因兼容跳转而保留，并缩减为实现跳转所需的最小内容；不得同时保留废弃的多页面展示实现。

## 10. 验证与验收标准

### 自动验证

- `bundle exec jekyll build` 构建成功，无 Liquid、数据或模板错误。
- `ruby scripts/verify_site.rb` 通过，并更新检查项以匹配新的单页结构与兼容跳转页。
- 构建产物中不存在空 `href`、关键旧 Tab 导航或移动菜单控制。
- 首页包含能力、经历、项目、文章和联系板块锚点。
- 文章详情页仍可从首页卡片访问。
- 仓库中不存在未被引用、且不承担兼容跳转或构建功能的废弃页面、组件、脚本与样式。

### 手动验证

- 桌面宽屏下，个人信息卡在滚动时保持可见且不遮挡内容。
- 手机与窄屏下，页面变为单列，信息卡取消固定并保持合理顺序。
- 浅色、深色主题均具备足够对比度，主题偏好可保存。
- 锚点跳转、兼容页跳转、文章详情链接及有效外部链接均正常。
- 键盘可以操作所有链接和主题按钮，焦点清晰可见。
- 减少动态效果偏好生效。
- 页面没有明显横向溢出、空卡片、空链接或未经确认的真实履历声明。

## 11. 完成定义

当首页已成为完整的一页式个人说明书、旧多 Tab 导航消失、项目与文章在页面内以卡片呈现、桌面侧栏能粘性滚动、移动端能自然降级、文章详情与旧入口兼容正常，并且自动与手动验证全部通过时，本次改版完成。
