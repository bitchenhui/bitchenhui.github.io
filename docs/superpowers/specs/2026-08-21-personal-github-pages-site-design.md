# 个人 GitHub Pages 网站设计

**日期：** 2026-08-21  
**状态：** 已确认，待实施计划

## 1. 目标与范围

为 `bitchenhui.github.io` 建设一个中文优先的个人网站，兼顾技术同行、招聘方 / 潜在合作方与普通访客。

首版包含：

- 个人名片式首页：个人定位、简短介绍和清晰的内容入口。
- 项目作品集：集中展示代表项目与外部链接。
- 技术博客：使用 Markdown 写作并支持文章详情、标签、归档入口和 RSS。
- 关于 / 简历页：个人介绍、技能、经历、教育背景及简历链接占位。
- 静态联系渠道：邮箱和社交链接；不加入评论、表单、登录或后端。
- GitHub Pages 部署与未来独立域名绑定说明。

首版使用清晰标注、可集中替换的示例资料，不伪造真实履历或项目成果。

## 2. 技术方案

采用 Jekyll 与自定义轻量主题。

- 使用 GitHub Pages 原生的 Jekyll 构建和发布能力，避免 GitHub Actions、服务器和数据库依赖。
- 页面模板由 Liquid、HTML、SCSS 和少量原生 JavaScript 构成，不引入前端框架。
- 使用 `_config.yml` 管理站点元数据、个人资料、社交链接、URL 和未来独立域名。
- 使用 `_data/projects.yml` 管理作品集数据；使用 `_posts/` 管理 Markdown 博客文章。
- 不添加 `.nojekyll`，以确保 GitHub Pages 会执行 Jekyll 构建。

## 3. 信息架构

```text
首页 /
├─ 首屏：个人定位、简短介绍、项目 / 博客入口
├─ 关于我摘要：工作方向与技能
├─ 精选项目：3 个项目条目
├─ 最新文章：3 篇最新文章
└─ 联系方式：邮箱和社交链接

项目 /projects/
└─ 完整项目卡片列表

博客 /blog/
├─ 文章列表：日期、标签、摘要
└─ 文章详情：/blog/<slug>/

关于 /about/
└─ 介绍、技能、经历时间线、教育、简历链接占位

其他
├─ RSS：/feed.xml
├─ 站点地图：/sitemap.xml
├─ robots.txt
└─ 自定义 404 页面
```

顶部固定导航提供“首页 / 项目 / 博客 / 关于”入口；小屏幕上切换为可展开菜单。首页首屏优先展示一句中文个人定位，并提供“查看项目”“阅读博客”等行动入口。

## 4. 视觉与交互

视觉方向为**浅色默认的科技极简**，以克制而不模板化的方式融合科技感。

- 使用暖白或极浅冷灰作为背景，深灰近黑作为主要文字。
- 使用低饱和蓝紫作为唯一强调色，覆盖链接、按钮、标签和焦点状态。
- 首屏可使用低对比度网格、细线或柔和光晕作为背景装饰，不干扰可读性。
- 使用中文友好的无衬线字体栈和等宽代码字体；标题层级清晰，整体留白充足。
- 默认浅色模式，支持手动切换至同样克制的深色模式。初始值尊重系统主题，手动选择保存至浏览器本地存储。
- 交互只包含短时、低位移的悬停与键盘聚焦反馈；不使用复杂动画或高饱和霓虹效果。
- 项目和文章卡片在移动端转为单列，保证字号、触控尺寸和内容阅读体验。

## 5. 内容模型与渲染流程

### 全局配置

`_config.yml` 维护站点名称、个人定位、简介、站点 URL、邮箱、社交地址和基础 Jekyll 配置。所有未知真实资料使用统一的 `TODO: 替换为…` 标记。

### 项目

`_data/projects.yml` 中每个项目包含：名称、简述、技术栈、封面可选描述、精选标记、项目链接和仓库链接。首页仅展示精选项目，项目页展示完整列表。缺失的可选链接不渲染按钮。

### 文章

`_posts/` 使用标准 Jekyll 文件名和 Front Matter。文章包含标题、日期、摘要可选、标签和分类可选。Jekyll 自动渲染文章详情、博客列表、首页最新文章及 RSS；缺少摘要时使用正文截取作为回退。

### 数据流

1. 在 `_config.yml` 填写个人资料和联系渠道。
2. 在 `_data/projects.yml` 添加或更新项目。
3. 在 `_posts/` 新增 Markdown 文章。
4. Jekyll 在本地或 GitHub Pages 构建中渲染所有页面。
5. 推送到 GitHub 的 `main` 分支后，GitHub Pages 自动发布，无需应用服务器。

## 7. 可访问性、回退与边界

- 使用语义化 HTML、逻辑标题层级、可见键盘焦点及足够的文字 / 背景对比度。
- 所有非装饰性图片提供有意义的替代文本；装饰性元素不干扰辅助技术。
- 缺失项目、文章或外部链接时提供友好空状态或隐藏对应控件，不能暴露空链接。
- 网站不采集访问者信息，也不配置登录、评论、数据库、表单或后端。
- 首版不会提交未知的 `CNAME`；未来绑定域名时，在 GitHub Pages 设置中填写域名、按 GitHub 指引配置 DNS、再在仓库中添加 `CNAME`，并启用 GitHub 提供的 HTTPS。

## 8. 首版示例内容

- 一段个人定位与介绍占位文案。
- 三个显式注明待替换的示例项目：视频编码优化工具、性能分析平台、个人开源工具。
- 三篇 Markdown 示例文章，涵盖编码性能、工程实践和工具链主题。
- 关于页中的履历、技能、教育及简历链接占位区。

## 9. 验收标准

1. GitHub Pages / Jekyll 构建成功，没有配置或模板错误。
2. 首页、项目页、博客列表、文章详情、关于页、RSS、站点地图和 404 页面均能访问。
3. 在桌面和移动视口中，导航、卡片、排版和主题切换均正常。
4. 主题切换能保存用户偏好，并在未设置偏好时合理遵循系统主题。
5. 不存在空链接、明显布局溢出或缺少替代文字的关键图片。
6. README 说明本地预览、发布、写文章、添加项目、替换个人资料和绑定独立域名的流程。
